# Domain documentation

This repository uses one root GLOSSARY.md and docs/adr/.

Before exploring an area:

- Read GLOSSARY.md if present.
- Read ADRs relevant to that area.
- Proceed silently when these documents do not yet exist.

Use the glossary's canonical terms in documentation, tickets,
code, and tests. Surface conflicts with existing ADRs explicitly.

Create glossary entries when terms are resolved and ADRs when
qualifying decisions are made; create documents lazily.
