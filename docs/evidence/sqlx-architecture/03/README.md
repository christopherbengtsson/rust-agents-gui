Retained action/workspace activities replace both active sentinels. A continuously reaped `JoinSet` dispatches independent effects concurrently. Weak keyed entries use the actual canonical common Git directory; physical workers and waiters retain their gate through completion. Read-only inspections have a separate bounded physical slot and keep their existing owning module. Status reads do not dispatch creation. Provider/Quit/root controls retain the incumbent bypass; workspace/repository status has separate bounded dispatch capacity. The incumbent outer eight-handler host cap is unchanged, so saturated whole-desktop control behavior remains a later host qualification limit.

Allocation uses indexed folder/name candidates and one atomic typed claim. Folder and footballer-name cursors are independent, checked, monotonic and persisted with the pending creation. Each turn attempts at most 32 candidates, persists its continuation and yields; global folder collisions cannot consume unused plain names. Eight pending actions bound ordinary admission and eight dispatched domain activities bound execution; these are resource safeguards, not repository/history cardinality limits. Recovery reuses an existing identity/slot. Metadata pages retain the existing 32-row/48 KiB bounds. Candidate-specific filesystem checks replace `read_dir` inventories; Git worktree/ref acquisition remains subject to the shared 256 KiB runner/deadline bounds. There is no load-all historical reservation set or tier sweep.

Expected claim conflicts explicitly roll back without poisoning writer admission. A failed or lost acknowledgment retrieves fresh same-action state after writer settlement before considering another candidate. Committed name, branch and path remain immutable. Creation retains its pinned base and existing ownership/partial-effect checks; it neither deletes unrelated artifacts nor changes original checkouts. Reconciliation carries its new action identity through execution while retaining the original creation identity and reservation.

The current schema is **3**, with independent cursor columns and an indexed cleanup-fence projection. Retired metadata is rejected with fresh-state guidance; there is no migration/import or silent reset. To reproduce, stop the owning application normally and choose a newly created private development root. Explicit overrides remain exact. Never replace an active database/WAL/SHM set or take over old worktrees. Qualification below uses only newly created disposable roots and leaves them retained.

`workspace-checkpoint` source-links the actual production storage, workspace, Git, private-file-validation and journal modules. It is a temporary verification entrypoint while provider callers prevent the whole core from compiling, with no alternate implementation or public product API. `corepack pnpm test:workspaces --measure` compiles that unit harness and executes only substituted units; it needs no staged sidecar.
