## Implementation and ownership

App constructs one Query client, physical coordinator, repository/workspace feature
modules, Zustand presentation identity store and existing inspection reader above
layouts. Query owns repository/workspace bodies and last-good data. The store holds
selected repository/workspace identities; existing preference records/errors remain
compatible. Reading-context persistence/integration remains F05. Connection status
and inspection keep their existing observation ownership.

Pinned **p-queue 10.0.0** replaces manual drain/count/queue mechanics. Two active
physical reads and 64 distinct relevant queued reads remain the limits; equivalent
requests still attach at capacity. The unsettled registry holds complete identity
and consumers only, including owner, operation, cursor and actual reprobe flags.
Queued-only cancellation cannot abort active IPC or free its slot; active identity
survives disposal and Query cancellation/remount until physical settlement. The
queue has no execution timeout. Only refreshable repository operations receive the
reprobe flag; action status and workspace reads retain their actual request identity.

Consulted the [versioned p-queue API/source](https://github.com/sindresorhus/p-queue/tree/v10.0.0)
and installed Query **5.107.1** declarations/source. Query uses local-IPC defaults:
networkMode always, automatic retry/focus/reconnect/mount refetch disabled,
feature-controlled freshness and five-minute inactive retention. Bounded list
validators and generated structural checks plus named semantic assertions remain
in the owning feature boundary. Screens receive observations and targeted callbacks,
without configuring Query keys, queues, generations or acknowledgements.

The existing feed controller calls a synchronous composition sink before cursor
advancement and acknowledgement. Concrete features map hints into a shared bounded
256-identity generation budget; overflow samples a global resync generation.
Inspection records its invalidations through that same budget without migrating its
cache or lifecycle. Initial feature reads wait for accepted baseline delivery.
Reads capture generations at physical start, so a coalesced remount cannot claim a
newer generation than its underlying exchange. Hidden targets retain independent
obligations; interested targets follow up after intervening hints. Errors preserve
last-good data without creating retry loops. Failed-read generations live with
Query errors, including their original typed causes, so interest release/remount
does not retry them. Both success and physical failure capture at physical start.
Explicit repository refresh retains up to three exact owner-bound targets across
temporary connection-interest detachment; obsolete/hidden flags expire after the
baseline attachment wave and replacement owners cannot inherit them.

Repository/workspace 250 ms progress/action/availability polling is removed.
Automatic reads always observe repository availability with refresh=false;
explicit reprobe remains separate. Existing inspection sequencing, error pause,
pending polling and visible two-second external-Git cadence remain. View cleanup
releases inspection interest; App owns the stable reader across keyed navigation.
F04f will replace its internals and the feed lifecycle with actors.

Retained actions preserve identity/payload before IPC, legacy records, sticky
uncertainty after later pre-send/local rejection, and explicit retry only. Lookups
match exact retained payloads. Captured callbacks retain observed owner/target;
settlement checks both owner and navigation generation. Rust remains authoritative
for reconciliation and execution; Query success alone is not execution evidence.
