## Delivery contract and publication audit

The supervisor hosts one concrete in-memory journal shared with workspace ownership.
It retains 256 entries, at most eight typed tags per entry; deliveries coalesce up
to 32 tags and enforce 4 KiB, inside the existing 64 KiB frame ceiling. Oversized
entry/batch or expired, missing, future and other-owner cursors request resync at a
sampled watermark. Sequence exhaustion closes visibly instead of wrapping or spinning.
New publications after the sampled watermark remain available after acknowledgement.
These cursors order hints; they establish no atomic snapshot of feature reads and
carry no paths, transcripts, provider tokens or durable conversation history.

| Owning transition                                                           | Published interests                                                                                                          |
| --------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------- |
| Registration admission, including failed potentially committed intent       | Registration action and repository feature                                                                                   |
| Registration completion / potentially committed finish                      | Registration action, repository feature, workspace collections; known successful repository and initial workspace identities |
| Availability Checking and available/unavailable results                     | Repository collection and exact detail                                                                                       |
| Workspace create/reconcile admission, including ambiguous failure           | Exact action plus associated collection; reconcile also identifies its workspace                                             |
| Creation/recovery active ownership, naming and persisted stages/results     | Workspace detail and repository workspace collection, including potentially committed write failures                         |
| Registration faults and clearing                                            | Repository feature, including retained pending registration interests                                                        |
| Workspace fault insertion/removal and active-owner clearing                 | Workspace detail and associated workspace collection                                                                         |
| Inspection record/queue and preview changes, including eviction             | Exact affected workspace inspection interests                                                                                |
| Inspection/preview running, ready/failed and refreshed-preview invalidation | Exact workspace inspection interest                                                                                          |

Collection hints cover related details and retained pending-action interests. Narrow
tags permit more selective work when identities are known. Hints never assert action
success. `OwnerGuard` releases owning state before waking subscribers, including error
and unwinding exits. Publication uses owner-state → journal lock order. Subscribers
never call domain modules under the journal lock; delivery performs no I/O under
owner/journal locks. Ambiguous workspace admission also wakes the existing owner worker.

Protocol 7 adds owner-bound subscribe, batch and acknowledgement contracts. The
[synthetic application corpus](../../../contracts/observations-v7.json) is checked by
Rust serialization and TypeScript production decoders; protocol-6 evidence is retained.
Older peers are rejected before domain dispatch, requiring matching desktop/supervisor
builds. Status revision and frontend-accepted feed sequence remain independent.

F03's reserved subscription permit is admitted before the physical thread starts.
One native subscription and one unacknowledged frontend delivery are permitted.
Ordered Tauri channels transport batches; exact subscription/batch/cursor acknowledgements
advance delivery. Heartbeats are five seconds; frame transfer has a two-second budget;
acknowledgement has a 15-second absolute deadline, including fragmented transfers.
Persistent readers retain buffered subsequent frames. Native/frontend failures stop
visibly; socket shutdown, condition-variable wake and owned join drain cancelled work.
Late setup and obsolete generations cannot replace current state or stop a newer ID.
The frontend also detects missing delivery after 15 seconds.

`App` owns the continuing feed. The controller records dirty targets or a full-resync
marker before acknowledging, without waiting for feature reads. Dirty retention
collapses to a full marker beyond 256 distinct targets. Reconnect passes the accepted
feed cursor, not status revision. Owner replacement resets acceptance and never grants
authority to start a competing supervisor or replay an action. Last-good feature data
and baseline polling remain; F05 will consume dirty state and prove push equivalence.
