## Contract and coverage

Protocol 6 retains the matching application-version requirement. Native/Tauri
feature calls carry caller-observed expected owner separately from durable payloads;
feature replies, including domain failures, carry serving owner. Rust rejects
owner mismatch before dispatch and checks reply kind/target. TypeScript checks owner
before decoding results or failures, then checks feature structure, full payload
identity, state variants and bounds. Status discovery alone learns a new owner.
Snapshot and desktop identity are runtime decoded; native snapshot cursor commits
reject invalid owner/PID/revision/version evidence.

Transport Busy/NotConnected/OwnerChanged/ReplyUnavailable and incompatibility remain
separate from domain rejection. Physical pre-send failures retain not-sent evidence;
partial write/read failures retain uncertainty without reconnect/replay. Busy is the
F02 contract; F03 still owns bounded admission and scheduling.

Pending presentation records persist uncertainty before IPC. Later local rejection
cannot erase an earlier uncertain attempt. Legacy records are read conservatively;
the existing over-budget-path correction remains valid because that payload could
never pass the native input bound. Matching action status, including the complete
registration continuation flag or workspace payload, settles the retained ID.
A late failure cannot resurrect an already settled registration. Reconnect only reads.
