## Behavior and agreed clarification

The footer gear is one typed Link composed through the existing Base UI Button,
with native-button behavior disabled and explicit link semantics. Keyboard activation
opens `/settings/general`. Settings replaces the workspace presentation, provides
its own navigation and General main landmark, and uses Empty with honest placeholder
text. The skip link follows the displayed main content. Supervisor diagnostics stay
separate. Original milestone 06 now has an explicit extension pointer to Settings →
Providers → Codex; no provider setup or account scope was implemented.

The user explicitly simplified the original direct-entry fallback during planning:
without a usable preceding app entry, Back/Escape **replaces Settings with home**,
even when a remembered destination exists. This overrides the older remembered-valid-
destination fallback in the parent spec. Normal app launch does not open Settings;
F07 adds no reload, external deep-link or reconnect machinery. The decision is also
recorded in the selected ticket for fresh sessions.

Navigation retains only ephemeral Settings-entry provenance, keyed to actual history
identity. `/settings` replacement preserves it; replacing an entry through an unrelated
destination cannot reuse old return authority. Back/Escape and browser Back return to
the preceding app destination, including its view; Forward can reopen Settings and
return again. The heading receives entry focus. Return waits for route settlement,
then focuses the remounted gear for a gear-origin visit, otherwise the main landmark.
The first focus implementation consumed the request before main mounted; the retained
failed check and subsequent settled-route fix establish that boundary.

Settings handles Escape at window bubble phase, after Base UI overlay dismissal.
Consumed, composing and repeated Escape events do not navigate. The controlled
portaled-dialog fixture verifies dismissal before Settings return; no artificial
controls were added to the placeholder.

The root observation/action composition, Query client, feed and inspection actor stay
alive. WorkspaceInspection unmounts and releases interest while physical work drains.
Zustand retains lightweight file/comparison/scroll/layout context; it holds no new
navigation authority or observation body. Returning and workspace switching restore
validated context; changed comparisons discard stale file/scroll identity.
