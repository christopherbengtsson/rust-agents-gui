## Ownership and replacement

Pinned **XState 5.33.4** and **@xstate/react 6.1.0**, retaining Query 5.107.1,
Zustand 5.1.0 and the existing p-queue physical coordinator. Consulted official
[XState invocation documentation](https://stately.ai/docs/xstate/v5/invoke),
[React selector documentation](https://stately.ai/docs/xstate/v5/xstate-react),
and the installed packages' public declarations/source and peer requirements.
A version-tagged GitHub source lookup failed; installed exact-version packages
provided the version-specific API checks. No performance improvement is claimed.

The feed's app-lifetime actor replaces its serial promise, lifecycle generation and
manual watchdog. Its typed state table covers idle/starting/live/stopping/stopped
and the transient decision state. Exact validation and synchronous feature
invalidation precede accepted-cursor advancement and acknowledgement; refetches do
not delay ack. Status revision never becomes the accepted feed cursor. Successive
batches may arrive before prior acknowledgement promises settle.

Stopping retains the latest desired configuration without starting a competitor.
The owner requests exact native stop, awaits setup and cleanup outcomes, and stops
again after registration to cover late attachment. A successful idempotent exact
stop/join response reconciles native absence; a rejected final cleanup remains
visible and fenced with the original subscription handle. Explicit reconnect
reconciles that handle. Existing Rust/native IPC contracts are unchanged. UI also
shows delivery failure while cleanup remains pending. Actor disposal is never
claimed as native cleanup.

The app-owned inspection reader now contains one XState lifecycle and its feature
Query definitions, physical requests, freshness/interests and comparison decisions.
Query is the sole body/last-good cache, using owner/operation/page/comparison/file
identity; refresh/load flags remain in physical request identity. Generated and
semantic validation still run through the existing workspace boundary. Actor
context holds IDs, keys, pending priority and physical handles rather than bodies.
Views use narrow XState selectors, Query observers and Zustand selection bindings;
view cleanup releases interest and drains actual work. The Hook requires the
app-owned reader and creates no fallback owner.

Accepted baseline gates initial inspection reads. Shared bounded dirty generations
retain hidden/resync obligations and hints during reads; each read satisfies only
the generation captured at physical start. One summary→preview sequence drains
before changed owner/workspace/file/page/visibility begins the latest eligible
sequence. First/Next retain comparison identity and queued explicit-refresh
priority; Refresh resets paging to First. Restored opaque file context is resolved
against the newly observed comparison before preview validation. In-memory selected
reading context moved into the app's Zustand presentation store. Durable preference
persistence, panel/reading-position integration and routing remain F05/later.

Covered 250 ms inspection pending/progress polling is removed. Push hints read
observations without repeated preview loads or summary refresh requests. Visible,
non-pending successful inspection retains the two-second external-Git refresh;
unrelated feed activity cannot postpone it. Errors retain last-good Query data and
pause automatic work until a newer hint or explicit refresh. Obsolete interest is
not shown as an application failure. Hidden/released interests start no reads while
physical work drains. Full owned Quit remains a later milestone requirement.
