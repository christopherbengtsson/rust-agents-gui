## Persistence and restoration

`persist` writes the new `agent-workspace.presentation` version-1 envelope.
`partialize` allowlists per-workspace selected file/path/comparison/reading position,
remembered view default and changed-file panel width/collapse. Explicit decoding
runs on hydration and serialization; saved fields cannot replace store methods or
introduce observations, transcripts, credentials or action authority. Synchronous
storage is an injected dependency. Read/parse/migration/future-version failures
show a persistent alert and preserve the original record, allowing in-memory use.
Write errors cannot recurse into another persistence attempt or interrupt UI work.
The alert remains visible with no mounted inspection.

Version 0 is an explicitly **synthetic compatibility contract** for lightweight
inspection selections with missing new context fields. It was never a shipped
persisted key. Migration normalizes it to version 1; unknown versions are preserved
and rejected visibly. Legacy repository/workspace selection keys remain compatible;
F06 owns their route migration. Pending registration/workspace keys, exact payloads
and sticky uncertainty are independent and survive both successful and rejected
presentation migration.

Remembered view initializes local tab selection; it is not current-route authority.
Completed keyboard/pointer resizes persist requested panel width; explicit collapse
preserves expanded width. Responsive remount uses the latest workspace context.
Diff position writes are coalesced to 150 ms, flushed on unmount and guarded by
workspace/comparison/file identity. A different file or changed restored comparison
cannot receive an old callback's scroll position.

Released/recreated views restore only matching comparison context, including native
validation of selected files outside the currently listed page. Changed comparisons
reject saved file/scroll context and require fresh selection. Live refresh preserves
existing behavior: Rust retains file IDs for surviving paths, exact current-target
preview validation continues, and new comparison context resets reading position.
Removed-file errors keep the named last-good preview. A late drained read cannot
turn a released selection back into live restoration.
