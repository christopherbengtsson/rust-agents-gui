## Mechanism and compatibility

`ConnectionSlots` now owns `Arc<Semaphore>` and uses `try_acquire_owned`;
`ConnectionPermit` aliases Tokio's owned permit. The existing `Admitted` worker
boundary and acquire-before-spawn callers stay intact. Observation/intent/status/
subscription budgets remain 2/1/1/1 and server capacity remains eight. No waiting
admission queue, custom counter or custom permit destructor remains. The existing
unwind test uses a narrowly explained `AssertUnwindSafe` because Tokio's permit
is not unwind-safe; it still verifies physical cleanup after a controlled panic.

Added exact **Tokio 1.54.1** and **tokio-util 0.7.20** with default features disabled.
Tokio selects `io-util`, `sync`, `time`; tests add `rt`, `test-util`. Tokio-util selects
`codec`, `rt` (CancellationToken requires the latter and enables Tokio runtime/sync
and futures-util). Direct buffer/trait imports use already locked **bytes 1.12.1**,
**futures-core 0.3.34**, **futures-sink 0.3.34**, with defaults disabled. No locked
package version changed. No net/process/multithread-runtime/full feature was added
by core, and core constructs a runtime only inside controlled unit tests.

Inspected the selected published Cargo registry sources, including codec head/body
reservation order, encode bounds, EOF handling, Framed ownership and Tokio features.
Supported-version references: [Semaphore](https://docs.rs/tokio/1.54.1/tokio/sync/struct.Semaphore.html),
[length codec source](https://github.com/tokio-rs/tokio/blob/tokio-util-0.7.20/tokio-util/src/codec/length_delimited.rs),
[feature source](https://github.com/tokio-rs/tokio/blob/tokio-util-0.7.20/tokio-util/Cargo.toml).
Consulted Rust design principles as tradeoffs, grounding this private mechanism in
the existing connection module rather than a configurable transport architecture.

`FramedExchange` takes exclusive ownership of an async transport and exposes only
complete payload reads/writes, clean boundary EOF and errors. `Framed` owns the sole
codec buffers. A small codec adapter retains incomplete-frame evidence; a stream
adapter observes first input without copying bytes. Four-byte big-endian u32 length,
zero offset/adjustment, four skipped bytes and **65,532 payload bytes** are explicit.
Encoding and decoding limits both come from LengthDelimitedCodec. Oversized headers
are rejected before reserving their body.

Reads accept an absolute operation cap. First input or buffered data starts one
two-second transfer budget capped by that original deadline. Dropping/recreating a
read polling future retains buffering and both deadlines. Writes encode once and
retain one frame through partial writes and flush, with one two-second budget
capped by the operation deadline. Explicit clock checks enforce caps even between
Tokio timer ticks. Cancellation wakes pending operations; errors, EOF and timeout
close the stream terminally. Dropping a polled write future closes too, preventing
restart of an incomplete send. Connection/domain callers retain delivery and retry
policy. A transport's Drop must close its exclusively owned resource; actual socket
qualification remains separate.
