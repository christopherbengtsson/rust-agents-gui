## Scheduling behavior and controlled coverage

Native admission belongs to Rust connection ownership. Immutable configuration and
client handles remain outside short observation-state locks. Owned admitted work is
obtained before Tauri spawns blocking tasks. Two observation slots, one intent slot,
and one status/discovery slot have independent nonwaiting budgets; the later
subscription has its separate reserved slot and no subscription implementation.
Busy is a transport NotSent result, distinct from domain Capacity/Conflict. Existing
owner binding, physical delivery evidence, protocol 6, framing bounds and
no-restart/no-replay recovery remain intact. Status alone commits connection state.
Supervisor client admission uses owned guards with the existing eight-peer ceiling.

App owns one frontend coordinator across repositories, workspaces and inspection.
It runs two physical reads and queues at most 64 distinct targets. Complete keys
include feature, owner, operation, target, cursor and flags; equivalent request
property order coalesces. Live duplicate interests share queued or active work,
including a new interest attaching after every earlier interest disposed. Obsolete
consumers remain obsolete. Scope disposal drops unneeded queued work; active work
retains admission until physical settlement. Inspection still owns its sequential
changes/preview lane and queued explicit refresh. Status drains separately through
Strict Mode reconfiguration; failed desktop-identity reads cannot release a still
running status exchange. Explicit durable submissions bypass read scheduling.

## Queue-overflow decision and handoff

Discard queued entries when their last interested consumer becomes obsolete.
If all 64 queued targets remain relevant, reject the newest distinct read with a
visible local Busy/NotSent observation error. Preserve admitted work and coalesced
interests; do not evict a still-needed target or automatically retry anything.

This defensive case requires two active reads, 64 distinct still-needed waiting
targets, then another distinct target. The current 32-repository page plus bounded
details/action/inspection reads should stay below it during ordinary navigation.
Navigation disposes obsolete interests and equivalent targets coalesce. A controlled
unit fills all 64 queued targets, verifies an identical target can still coalesce,
and verifies only the extra distinct read is rejected. The user accepted the
recommendation and requested that the completed session handoff retain the decision.
