## Implementation and compatibility

Both native peers and the feed now use **protocol 8** and F04c's single private
`FramedExchange`: four-byte big-endian u32 length, **65,532 payload bytes**, and
**65,536 total wire bytes**. The codec retains the sole framing buffers across
handshake, feed and acknowledgement boundaries. Retained kernel coverage includes
strict EOF, first-data transitions, buffered frames, absolute transfer/write caps
and terminal cancellation. Version/application/owner/context checks precede domain
dispatch. Legacy framing is closed without dispatch or fallback; client failures
remain visible. An established connection loss cannot trigger discovery/start or
action replay. Target/reply validation and per-attempt delivery evidence remain
in connection policy; retained frontend action tests preserve earlier uncertainty
after Busy, owner or local rejection.

Supervisor main continuously drives one current-thread Tokio runtime with I/O/time.
Tauri commands use its existing runtime and await targeted Rust work. The core
constructs no production runtime. Async client APIs, prepared-request completion,
server hosting and gated qualification callers were updated together; frontend
command arguments, replies/events and generated contract shapes remain compatible
with F04b.

Pinned Tokio **1.54.1** and tokio-util **0.7.20** are retained. Core now explicitly
selects `net` and `rt` in addition to its existing features; supervisor directly
selects its runtime/network/time dependencies and the already locked futures-util
**0.3.34** `std` feature for cancellation-safe accept/completion selection. No
locked package version changed. Consulted selected-version
[runtime](https://docs.rs/tokio/1.54.1/tokio/runtime/struct.Builder.html),
[JoinSet](https://docs.rs/tokio/1.54.1/tokio/task/struct.JoinSet.html), retained
F04c codec evidence and the repository's Rust design-principle guidance.

Nonwaiting desktop lanes remain **2 observation / 1 intent / 1 status / 1 feed**;
supervisor remains **eight clients**. Connection owns a completion registry:
`Admitted::run` transfers the permit into physical async work before returning a
disposable result waiter. Completed tasks are reaped and cleanup observes joins,
including panics. Filesystem/private-access/discovery work is admitted to a shared
five-worker desktop blocking budget; supervisor domain dispatch has an eight-worker
budget. Blocking closures own their permits through actual completion, even after
waiter cancellation. Main retains handler capacity while dispatch completes and
collects finished handlers before accepting more clients. Startup owner admission
and core opening remain serialized before serving. The existing intentional child
process reaper remains: the independently owned supervisor outlives desktop loss.
It is distinct from the removed detached connection workers.

Native feed ownership now retains an async task, CancellationToken, exact pending
acknowledgement and awaited cleanup. Setup is registered before returning; exact-ID
stop is idempotent. A dropped stop waiter leaves its task handle with the owner,
and replacement remains Busy until physical cleanup joins. Cancellation wakes
socket/frame, frontend-ack, journal and startup-delay waits. Error/panic completion
is observed; app cleanup drains requests even if feed cleanup reports an error.
The five-second heartbeat, 15-second acknowledgement cap, two-second transfer cap,
one native delivery in flight and accepted-feed/status cursor separation remain.

The concrete bounded replay journal is retained. Async notification is registered
before inspecting its protected predicate; publication remains under domain
protection and wakes after unlocking. No domain call occurs under the journal
lock. Overflow/resync, changes during resync, exhaustion and publication-before-wait
remain covered. No broadcast queue replaces the journal.

Removed synchronous newline framing, libc readiness polling, per-socket timeout
configuration, subscription threads/Condvar/socket-clone shutdown and superseded
connection workers. Necessary blocking domain/Git/storage/process implementations
and their effect seams remain.

the discovery sleep ignoring cancellation before their fixes. Early compilation
attempts retained an unsupported async-trait future bound and mechanical async
qualification-caller conversion errors; stable owned-future bounds and corrected
callers pass configured static checks. An intermediate missing test-module directory
was fixed. Existing ts-rs unsupported-Serde diagnostics remain visible.

packaging, hosted CI and native-provider qualification are **not run**. No provider
submissions occurred. Passing units establish controlled application policy, not
actual OS socket cleanup, private access, desktop responsiveness or provider
compatibility. Those actual qualification requirements remain F04g and later
milestone work. Full owned Quit remains outside F04d.
