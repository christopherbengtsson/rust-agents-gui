## Catalog cost

The actual catalog contains **6,531 UTF-8 slug bytes + 8,000 bytes of 64-bit string-slice entries = 14,531 logical bytes**. No runtime download or dependency is added. A catalog-only controlled production build with the retained 112 versus all 500 names produced the same **3,211,280-byte** supervisor file size, and therefore **0 measured file-byte delta** in an uncompressed private bundle-copy resource replacement. Link padding can obscure logical growth; this is not a claim of zero data cost or a second signed/compressed-package comparison. The source was restored, rebuilt and its original full-catalog binary hash matched. [Sizes and experiment details](readable-workspaces/catalog-size.json). Final formatting/repackaging has its separate provenance above.

The [standalone measurement harness](readable-workspaces/measure_catalog.py) compiled the production policy/catalog with inert unused identity/error record types (only the catalog module path was adjusted). One warm-up + five 10,000-selection runs, Rust opt-level 3: median **10.126 µs** with no reserved plain names, **13.831 µs** at half, **13.447 µs** at 495, **48.926 µs** when all 500 plain names were reserved. [Ranges/source hashes](readable-workspaces/catalog-performance.json). This excludes Git, SQLite, IPC and UI and does not claim end-to-end latency.
