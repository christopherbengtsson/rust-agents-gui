## Delivered behavior and successor interfaces

`runtimes::ProviderConnections` owns readiness admission, last-good evidence,
refresh coalescing, result generations and physical cleanup fencing. Its concrete
Codex adapter implements only version checking, initialize/initialized,
`account/read` with `refreshToken:false`, and `config/read` with
`includeLayers:false`. Provider framing is newline JSON, bounded to 256 KiB with
strict request correlation, bounded notifications and an absolute 15-second setup
budget; version reads have five seconds. Server requests are rejected, never
approved. Runtime-owned configuration/credentials are neither edited nor exported.

The same command/parser/process path runs the controlled fixture child. Process,
stream/time and owning-policy units substitute outcomes and retain real command
construction/parsers. EOF/TERM/KILL cleanup uses two-second phases. The unreaped
leader retains process-group identity until macOS `waitid(WNOWAIT)` and bounded
libproc enumeration establish group quiescence and pipe completion. Unknown
completion retains handles and fences replacement. The selected SDK's
`sys/proc_info.h`, `sys/wait.h`, libc 0.2.191 and Apple's
[libproc wrapper source](https://github.com/apple-oss-distributions/xnu/blob/main/libsyscall/wrappers/libproc/libproc.c)
supply the native API contracts. A child exit alone is insufficient.

The actual readiness interface for 02 is:

- `ProviderRequest::Target` retrieves the default descriptor without spawning a
  runtime. `Observe { target_id, refresh }` returns an immediate owner-bound
  snapshot; initial observation admits one job and explicit Refresh coalesces
  with active work. Reconnect/navigation only retrieve its status.
- `ProviderTarget.id` is an opaque configuration-scope UUID within the exact
  supervisor owner. The descriptor records executable, Codex home, neutral cwd and
  supported version. The concrete private `Launch` retains the effective inherited
  environment and normalized Codex home. Successor login must extend this captured
  launch/owner, not reconstruct it from the inspected tab or workspace selection.
- `ProviderObservation` contains revision/phase, retained authentication/account/
  configuration/billing evidence, recovery category and bounded sanitized
  diagnostics. Internal `SetupFailure` keeps I/O sources; projections keep
  operation/kind/OS code, RPC code, parse location, exit/deadline context without
  raw provider messages. Unknown/custom billing stays unknown.
- One app-scoped `ProviderObservations` uses the existing Query client, accepted
  feed/freshness and physical scheduler. Generated validators precede owner/target
  semantics. `useProviderSetup` subscribes directly to stable Query snapshots;
  presentation acquires/releases interests without owning probes or retries.
