## Delivered behavior and ownership

Providers keeps existing authentication/readiness first and adds the explained
ChatGPT/browser action below account facts, outside collapsed help. Browser
handoff is explicit; reopening uses the original attempt. Starting, pending,
cancelling, verification, success, failure, cancelled and uncertain-cleanup states
remain distinct. Completion rechecks authoritative account/configuration and does
not navigate or start agent work. Failed verification retains Last known evidence.
CLI/PTY, API-key setup and Claude execution were not implemented.

`runtimes::ProviderConnections` owns admission, exact attempts, scope exclusion,
readiness verification, cancellation, stale-result rejection and reconciliation.
The Codex adapter alone owns initialize/login/cancel/completion protocol details,
the native login ID and URL. URLs and provider credentials never enter the
frontend observation, application history or diagnostic log. Native opening uses
an owned `/usr/bin/open` child; browser-opening failure does not start another
authentication attempt. Browser applications themselves are user-owned.

Application attempts are UUIDs distinct from target and native login identity.
Requests bind the expected supervisor, exact configuration target, attempt and,
for start, expected revision. Reconciliation observes an admitted attempt or
advances the admission revision to fence an absent but delayed start. It never
repeats start/cancel effects. Same-credential-scope checks/authentication/uncertain
cleanup exclude each other; unrelated synthetic targets progress within budgets.
The owning module retains task/process handles until physical cleanup is observed.
A loop-top absolute deadline prevents queued reopen requests from starving timeout handling.

SQLite stores only scope, application attempt ID and pending-cleanup evidence in
`provider_login_fences`. Intent commits before authentication; cleanup evidence
commits before releasing admission. An unclean supervisor loss retains a visible
durable scope fence rather than pretending orphan cleanup succeeded. Automatic
orphan reclamation/unfencing is not implemented, and no saved PID is signalled.
Normal desktop crash/reconnect retrieves the still-running supervisor's attempt.

Query remains the sole observation cache. Pending-action metadata contains only
identities/delivery feedback. App-level interests retain both target descriptor
and attempt observation across routing, cache expiry and transport disconnection.
Pure status reads have no process effects; committed Codex-tab entry still sends
one explicit readiness refresh. Native Quit fences startup, reconciles a failed
initial connection or observes its owner, requests owned cleanup and waits for
supervisor lock release before desktop exit. Window close hides, and macOS Reopen
restores the window. Failed/unknown shutdown remains visible.

Current supervisor protocol is **12**. Use matching peers and fresh private
development state; previous formats require no compatibility reader/migration.
Ticket 03 extends these actual interfaces:

- `ProviderRequest::Target` and pure `Observe { target_id, refresh: false }` retrieve
  status; `refresh: true` requests readiness admission through the same owner.
- `StartBrowserLogin { target_id, attempt_id, expected_revision }`,
  `CancelLogin`, `ReopenBrowser`, and `ReconcileLogin` target exact attempts.
  Replies remain owner-bound `ProviderReply`; observation includes `LoginAttempt`
  with separate phase/outcome, browser-open feedback and sanitized diagnostics.
- Private `admit_login`, credential-scope admission, persistence and cleanup
  coordination are the shared attempt seam. Extend it for CLI; do not add another
  execution/retry authority. Browser-specific `BrowserEffects` is a private effect
  substitution, not a required provider capability interface.
- `BeginShutdown`, `ShutdownStatus`, and `FinishShutdown` establish owned physical
  completion before supervisor exit. Tauri's custom Quit menu routes through this
  path; the predefined macOS Quit bypass was corrected and actually qualified.
- `ProviderObservations`, `useProviderSetup`, `useProviderLogin` and
  `useProviderProgress` share generated validation, Query, feed freshness and the
  existing physical scheduler. The optional supervisor snapshot progress flag
  discovers an existing attempt on desktop reopen. No renderer owns auth state.
