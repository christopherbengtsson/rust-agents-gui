## Delivered behavior and handoff

- Providers uses the existing line tabs, a bounded content column and compact
  account/plan/billing facts. Model/configuration, runtime paths and diagnostic
  context start collapsed in Technical details; general external guidance starts
  collapsed in Setup help. Relevant recovery remains visible.
- `StatusIndicator` is a presentation-only product primitive with `tone` and text
  `label`, a decorative 7 px light, a static success halo and polite atomic status
  announcements. Its semantic colors come from the existing theme. Badge retains
  its enclosed-label role; the installed Badge's overflow/padding/shape do not fit
  the requested inline halo. No upstream component was added or regenerated.
- Healthy setup has no Refresh or Check again, including in details. Pending
  verification uses a neutral Checking indicator; stale evidence is Last known.
  Failure/missing setup provides contextual Check again; disconnected and cleanup
  uncertainty states explain why a new check is unavailable.
- A committed `useProviderSetup` activation marks one targeted verification through
  the existing `ProviderObservations.refresh` before attaching readiness interest.
  It defers setup to skip disposed Strict Mode mounts and retains only a consumed
  intent marker across reconnect, not another copy of evidence. Query remains the
  cache. Target preloading, rerendering, dirty hints and reconnect do not replay the
  activation. A new actual Codex-tab activation verifies again.
- Rust still admits/coalesces readiness checks and fences cleanup. Native code,
  generated contracts and protocol **11** are unchanged. The existing `Observe {
  target_id, refresh }` interface is reused. Initial disconnected entry waits for
  an owner/descriptor; consumed entry requests are not retried on reconnect.
- The shared spec and all four ticket handoffs record the prospective requirement
  change. 02 adds visible ChatGPT sign-in beneath readiness; 03 adds CLI alongside
  it. Both retain automatic verification after login and must coordinate checks
  with active authentication inside the same Rust owner. Login controls stay
  outside collapsed help. 04 qualifies the combined journey. Historical checked
  acceptance and evidence were preserved.
